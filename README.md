# Мультиагентный ассистент для обзора научных статей

Лабораторная работа №2 по дисциплине «Разработка AI-агентов».

Ассистент на LangGraph собирает научные статьи с [КиберЛенинки](https://cyberleninka.ru) и отвечает на вопросы по ним со ссылками на источники.

## Архитектура

Граф LangGraph из [assistant.py](assistant.py):

- **Оркестратор** (`qwen3:4b`) выбирает действие по сообщению пользователя: `collect` (собрать статьи), `research` (ответить на вопрос) или `offtopic` (отказ). Короткие уточнения вроде «Расскажи подробнее» относит к предыдущему вопросу.
- **Сборщик** ([collector.py](collector.py), `qwen3:8b`) ищет статьи через MCP-сервер, оценивает их релевантность от 0 до 10 и сохраняет в Qdrant статьи с оценкой от 6. Эмбеддинги строит `bge-m3`.
- **Исследователь** ([researcher.py](researcher.py), `qwen3:8b`) работает по схеме RAG: берёт из Qdrant до 5 ближайших статей со сходством не ниже 0.45, пишет ответ со ссылками `[n]` и добавляет список источников.
- **Рецензент** ([reviewer.py](reviewer.py), `qwen3:8b`) проверяет, что каждое утверждение подтверждено фрагментом. При вердикте `revise` ответ уходит исследователю на доработку, всего не больше двух кругов.

Сервисы:

- **MCP-сервер** [cyberleninka_mcp.py](cyberleninka_mcp.py) на порту 8001 (`/mcp`, streamable HTTP) с инструментами `search_articles` и `get_article`.
- **Рецензент по A2A** [reviewer_a2a.py](reviewer_a2a.py) на порту 8002. Оркестратор обращается к нему через [a2a_client.py](a2a_client.py). Если рецензент недоступен, ответ выдаётся с пометкой «не проверен».
- **Qdrant** на порту 6333, коллекция `articles_lab2`.
- **Память диалога** хранит `AsyncSqliteSaver` в файле `memory.db`, у каждой сессии своя история. В Docker файл лежит в томе `assistant_memory`.

## Файлы

| Файл | Назначение |
|---|---|
| `assistant.py` | Граф LangGraph: оркестратор, узлы агентов, чат в терминале |
| `collector.py` | Агент-сборщик: поиск через MCP, оценка релевантности, запись в Qdrant |
| `researcher.py` | Агент-исследователь: поиск в Qdrant и ответ со ссылками |
| `reviewer.py` | Агент-рецензент: проверка ответа по фрагментам |
| `reviewer_a2a.py` | Рецензент как A2A-сервис (порт 8002) |
| `a2a_client.py` | A2A-клиент, через который оркестратор обращается к рецензенту |
| `cyberleninka_mcp.py` | MCP-сервер для КиберЛенинки (порт 8001) |
| `check_mcp.py` | Тестовый клиент MCP-сервера: выводит список инструментов, ищет статьи и загружает одну по ссылке |
| `Dockerfile` | Общий образ для всех Python-сервисов |
| `docker-compose.yml` | Сервисы `qdrant`, `mcp`, `reviewer`, `assistant` |
| `requirements.txt` | Зависимости Python |

`collector.py`, `researcher.py` и `reviewer.py` можно запустить и отдельно, чтобы проверить агента без графа.

## Требования

- Docker Desktop.
- [Ollama](https://ollama.com) на этом же компьютере (порт 11434). Контейнеры обращаются к ней по адресу `host.docker.internal`. Модели:

```bash
ollama pull qwen3:8b
ollama pull qwen3:4b
ollama pull bge-m3
```

## Запуск

Том для Qdrant объявлен внешним, поэтому его нужно один раз создать вручную:

```bash
docker volume create qdrant_data
```

Запустить Qdrant, MCP-сервер и рецензента:

```bash
docker compose up -d --build
```

Открыть чат (вместо `<сессия>` подставьте любое имя, у каждой сессии своя история):

```bash
docker compose run --rm assistant <сессия>
```

Чтобы выйти из чата, отправьте пустую строку. Остановить сервисы:

```bash
docker compose down
```

## Примеры запросов

```
Собери 5 статей про блокчейн в медицине
Что пишут про блокчейн в медицине?
Расскажи подробнее
```

Первый запрос отправляет сборщика за статьями, второй передаётся исследователю, третий уточняет предыдущий вопрос.
